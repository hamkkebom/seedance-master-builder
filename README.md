## 사용 방법

1. **`seedance-master-builder.html`** 을 브라우저에서 엽니다 (더블클릭 또는 아래 서버 방식)
2. 왼쪽 패널에서 축을 선택합니다 — **① 작업 유형부터 시작** (나머지 필수 축은 빨간 경고 표시)
3. 오른쪽 **✍️ 콘텐츠 입력** 패널에 주체·사건·장면·대사·끝 상태·**CTA**·**첫 3초 훅**을 채웁니다 — **⏱️ 장면 타임라인**(구간별 장면/대사/카메라)과 **👥 주체 바인딩 매트릭스**(주체↔이미지/오디오 번호)는 자동 반영
4. 오른쪽 프롬프트가 실시간으로 **자연어 문장**(`镜头 N(시간)：...`)으로 조립됩니다
5. **🎤 인터뷰로 시작**: 툴바 "🎤 인터뷰로 시작" → 유튜브 쇼츠 광고·라이브 커머스·사주천궁 드라마·K-드라마·사극·먹방 중 선택 → 주체·사건·장면·대사·끝 상태·전체 톤·훅·CTA 질문에 답하면 한 번에 구성
6. **🌐 버튼**으로 프롬프트를 중국어 원문 ↔ 한국어 해석으로 전환해 확인 가능
7. **📋 프롬프트 복사** → Seedance 2.5 (즉몽/豆包/API)에 붙여넣기
8. **후편집**: 자막·브랜드 로고·CTA 문구·앱 UI는 AI 생성 대신 **편집 프로그램에서 합성** (텍스트 깨짐 방지)

## 핵심 규칙 (공식 문서 근거)

### 1. 작업 유형과 "有锁定"
- **편집 / 연장 / 시작·끝 프레임** = "有锁定" — 출력 비율·길이가 입력 영상에 고정됨
  - `ratio=adaptive` 강제, 편집은 `duration=-1` 강제
  - 위반 시 `InvalidParameter.TaskTypeConstraint` 비동기 오류
- **트리거 키워드 필수**:
  - 편집: `编辑视频 / 增加 / 删除 / 修改 / 替换 / 改成`
  - 연장: `向前/向后延长 / 延续 / 续写`
  - ⚠️ 참조(参考生视频) 프롬프트에 이 단어를 쓰면 **오판**되어 오류 발생

### 2. 타임스탬프 = 2.5 전용
- Seedance 2.0은 장면 번호(镜头N)만 응답, **2.5는 정수초 타임스탬프 응답**
- 시간 구간은 연속·비중첩: `0-4秒, 4-9秒, 9-14秒...`
- 빈도 제어 금지 (예: "1초에 3회 고개 흔들기")

### 3. 소리 특수문자 (공식 기호)
```
음악 ( )   → (가벼운 어쿠스틱 기타)
효과음 < > → <파도 소리>
대사 { }   → {안녕하세요}
자막 【 】  → 【제1장: 출발】
```

### 4. 대사 언어·억양 (한국어 전용)
- **대사는 한국어만** — 중국어 외 대사는 **대사언어 명시 필수**: `台词语言：韩语，自然的首尔口音`
- **⑤ 대사 언어·억양 축**에서 억양 선택 가능: 서울(권장·Runware 발음 고정 검증) · ⚡경상도(부산·대구) · ⚡전라도 · ⚡충청도 · ⚡강원도 · ⚡제주도 사투리 — 사투리는 사용자 파생(⚡확장)
- "서울 억양"까지 명시하면 발음 고정이 안정적 (Runware 검증)

### 5. 실사 vs 애니메이션 (스타일 고정)
- **⑳ 시각 스타일**에서 실사/2D/3D/사이버펑크 등 선택
- **㉑ 스타일 고정**에서 "정방향+역방향" 선택 시 **【严格排除】** 자동 생성:
  - 실사 고정: `黑白、手绘、线稿、插画、漫画、动画、塑料 CG` 금지
  - 2D 애니 고정: `真人实拍、3D CG渲染` 금지
- 공식 문서(2607689)의 정방향+역방향 2중 서술 방식

### 6. 1컷 1운경
- 한 컷에 카메라 움직임 **1종만** (푸시+팬 동시 금지)

### 7. 파라미터 (프롬프트에 넣지 않음)
- 비율·길이·해상도·포맷 등은 **API/페이지 설정** (프롬프트에 넣으면 공식 규칙 위반)
- 빌더 하단 "생성 파라미터" 패널에서 설정 → 복사

### 8. 복수 화자 목소리 분리 (⑥-3)
- 화자 2명/3명 선택 → **【人物声音设定】** 블록 자동 생성 (역할 + 성별·연령 + 음색 + 속도 + 감정기조)
- 전역 "목소리가 서로 섞이지 않게" 문구 자동 포함 — 2.5 오디오 참조(音色) 기반

### 9. 전역 블록 자동화
- **⑩-2 장면 독립 원칙** → 【镜头切换原则】 (각 컷 완전 분리·배경/의상/소품 전환 명시)
- **⑧ 감정 전환 = 전역 감정 아크** → 【情绪转折】 (시작→중간→끝 단계별 자연 전환)

## 🧩 AI 컴포저 탭 구조 (탭 추가 방법)

AI 컴포저의 탭(한 번에 구성 · 💬 자유대화 · 🔁 영상 업그레이드 …)은 **탭마다 독립된 `<script>`** 로 붙습니다.
탭 코드 하나가 망가져도(문법 오류·실행 오류) 그 탭 버튼만 사라지고 상태줄에 「○○ 탭을 불러오지 못했습니다」가 뜨며, 메이커 본체와 다른 탭은 그대로 동작합니다.

| 구분 | 위치 | 내용 |
|---|---|---|
| 본체 스크립트 | `seedance-master-builder.html`의 첫 `<script>` | 41축·프롬프트 조립·프리셋·인터뷰 + **탭 틀 `AITabs`** + **AI 탭 공용 도구** |
| 탭 스크립트 | 파일 맨 아래, 탭마다 `<script>` 하나 | 그 탭의 화면 동작만. 마지막에 `AITabs.register({...})` |

**새 탭 추가 (HTML 패널 1개 + script 1개 + 테스트 기대값 1줄)**
1. HTML — `#aiComposerForm` 안에 패널 추가 (탭 버튼은 만들지 않음, 등록하면 자동 생성)
   ```html
   <div class="ai-panel" id="aiPanelXxx" data-tab-label="탭 이름" hidden> … </div>
   ```
2. JS — 맨 아래 탭 스크립트들 옆에 `<script>` 하나. 본문은 함수로 감싼다(탭 안 이름이 밖으로 새지 않음)
   ```js
   (() => {
     async function xxxRun() {
       const credentials = readDeepSeekCredentials();
       if (!credentials) return;
       await runAIJob(async () => { /* AI 호출 */ }, [credentials.apiKey], { onStart() {}, onError(e) {}, onFinally() {} });
     }
     AITabs.register({
       key: 'xxx', label: '탭 이름', panelId: 'aiPanelXxx', order: 40,   // order = 탭 순서
       onShow() {},           // 탭을 열 때 (선택)
       onSubmit: xxxRun,      // 이 탭에서 Enter로 폼 제출할 때 (선택)
       setLocked(busy) {}     // AI 호출 중 이 탭 입력칸 잠금 (선택)
     });
   })();
   ```
3. 테스트 — `maker-tests/specs/smoke.spec.js`의 탭 목록 기대값에 새 탭 key를 추가한다.

**규칙**
- 탭끼리 서로의 함수를 부르지 않는다. 여러 탭이 같이 쓸 것은 본체의 「AI 탭 공용 도구」로 올린다 — `runAIJob`(잠금·오류 표시·잠금 해제), `readDeepSeekCredentials`, `getMakerSnapshot`(현재 설정 읽기), `normalizePlanCard`·`runAIComposer(…, { plan })`(기획 카드 → 메이커 적용), `loadMyDefaults`·`applyMyDefaultsToPlan`, `setMakerDurationSeconds`·`setMakerRatio`(쓰기), `escapeHtml`.
- AI 호출 잠금은 `runAIJob`만 켜고 끈다. 상태는 `AITabs.isBusy()`로만 읽는다.
- 탭은 `state`·`contentInput`·`p_ratio` 같은 메이커 내부 값을 직접 읽거나 쓰지 않는다 — 위의 읽기·쓰기 창구만 쓴다.
- HTML에 문자열을 끼워 넣을 때는 `escapeHtml`을 거치거나 `textContent`를 쓴다.
- 탭이 준 함수(`onShow`·`onSubmit`·`setLocked`)는 `AITabs`가 오류를 잡아 부른다.

## 🔌 개발자 통합 가이드 (LLM → 빌더)

이 저장소는 단일 HTML 빌더일 뿐 아니라, **LLM이 정해진 41축 틀에서 벗어나지 않고 축·키를 선택**하도록 하는 개발 통합 자산을 포함합니다. "사용자 대화 → 축 선택 → 프롬프트 생성" 파이프라인을 자체 앱에 붙이는 방법입니다.

### 통합 자산 구성

| 자산 | 역할 |
|---|---|
| `axes.json` | 41축(id·tag·type·requires·dependsOn·옵션 키) + 프리셋 37종 레지스트리. **원본은 HTML의 `AXES`이고 이 파일은 `node tools/sync-axes.mjs`로 생성**한다 — 직접 고치지 말 것 (`seedance-llm/axes.json`도 같은 파일) |
| `PROMPT_LLM.md` | LLM 시스템 프롬프트 — 축 사용 규칙·4기호·출력 JSON 계약 (LLM에 주입) |
| `seedance-llm/seedance-schema.js` | JSON Schema 생성기 — task 확정 후 유효 축만 enum으로 강제 (`additionalProperties:false`) |
| `seedance-llm/seedance-validate.js` | 서버 검증기 — 무효 키 오류 · dependsOn 자동 정리 · 콘텐츠 규칙 |

### 사용 플로우 (task-first 2단계)

```
1. buildTaskSchema() → LLM에 {task: enum 5종} 스키마 제시 → task 확정
2. buildStateSchema(task) → task에 맞게 프루닝된 축 스키마 → LLM이 축·콘텐츠 JSON 반환
3. validate(response) → { ok, axes, content, warnings, errors }
4. errors 있으면 구조화된 오류 배열을 LLM에 돌려 재시도 (최대 2회)
5. axes → 빌더 state에 반영 → renderPrompt() → 최종 프롬프트
```

### Node 예시

```js
const { buildTaskSchema, buildStateSchema } = require('./seedance-llm/seedance-schema');
const { validate } = require('./seedance-llm/seedance-validate');

// 1) task 결정
const taskSchema = buildTaskSchema();          // { task: enum[t2v,r2v,edit,ext,fl] }
// 2) task에 맞는 전체 스키마 (edit는 카메라 등 15축 자동 제외)
const schema = buildStateSchema('t2v');
// 3) LLM 응답 검증 (무효 키·dependsOn 자동 정리)
const result = validate({
  axes: { task:['t2v'], genre:['kdrama'], duration:['20s'], lang:['ko'],
          emotion:['flutter','joy'], camera:['B'], audio:['mus'], musicgenre:['ballad'], quality:['hd'] },
  content: { subject:'카페 테라스의 두 사람', dialog:'너랑 있으면 좋아' }
});
// 4) result.ok === true → axes를 빌더 state에 적용, renderPrompt()로 프롬프트 조립
```

### Python (pydantic) 예시

```python
from pydantic import BaseModel, ConfigDict
from typing import Literal

class BuilderState(BaseModel):
    task: Literal['t2v','r2v','edit','ext','fl']
    duration: Literal['10s','15s','20s','30s','auto']
    emotion: list[Literal['joy','sad','anx','angry','relief','embarrassed','flutter','fear','amused','aegyo','burst','choke','cheer','dazed']] = []
    model_config = ConfigDict(extra='forbid')   # additionalProperties:false 대응
```

### 검증 규칙 (LLM이 틀을 벗어날 때)

- **무효 키**(축 옵션에 없는 값) → `errors[]` 반환 → 재시도. 절대 "가까운 키"로 임의 보정하지 않음
- **dependsOn 위반**(예: audio에 `mus` 없이 musicgenre 선택) → **자동 초기화** + warning (빌더 `cleanupDependsOn`과 동일 시맨틱)
- **requires 위반**(task=edit인데 camera 선택) → 자동 제외
- **대사 `{}`** → 검증기가 제거, 빌더가 `台词语言：韩语…她说：{…}` 재부착

### 키 변경 워크플로

축·키 추가/삭제 시: **빌더 HTML의 `AXES` 수정 → `node tools/sync-axes.mjs`(axes.json 2개 재생성) → 커밋.** 잊으면 CI의 `sync-axes --check`가 실패합니다. 사람 전용 값(`manualOnly`, 예: 길이 직접 입력)은 LLM 스키마에서 빠지고 검증기는 유효로 받습니다. LLM_RULES.md §13 축 요약은 axes.json의 생성 뷰입니다.
